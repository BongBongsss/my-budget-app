# Make 월간 가계부 리포트 운영 안내

운영 서버의 요약 API와 Make 시나리오를 연결하고 사용자가 시나리오를 활성화했다. 첫 예약 발송은 아직 확인하지 않았다. API는 메일 발송이나 발송 기록을 직접 처리하지 않는다. (§D62)

## 요약 조회

- `GET /api/integrations/make/monthly-report?period=YYYY-MM`
- `Authorization: Bearer <MAKE_REPORT_TOKEN>` 헤더를 사용한다. 토큰이 없거나 32자 미만이면 조회가 비활성화된다.
- 설정값은 `MAKE_REPORT_TOKEN` 환경변수이며, 무작위로 생성한 충분한 길이의 전용 값을 사용한다. 토큰과 비밀번호는 채팅·URL·문서·Git에 남기지 않는다.
- 결과에는 `subject`, `html`, `text`, `summary`가 있다. 승인 거래와 통계 제외 설정을 적용하며, 미승인 집계는 활성 임포트 행을 포함한다.
- 응답은 민감한 가계 요약이므로 `Cache-Control: no-store`를 사용한다. Make의 실행 기록과 메일함에도 정보가 보관될 수 있으므로 접근 권한과 보관 설정을 확인한다.
- 날짜는 명시된 월의 가계부 기록 기준이다. `period`는 `2026-10` 같은 형식이며 누락·잘못된 값은 거부한다.

## 현재 Make 구성

1. 매월 28·29·30·31일 오전 08:00에 `Asia/Seoul` 시간대로 실행하고, 다음 날의 일이 1일인 경우만 통과시킨다.
2. HTTP 요청은 `formatDate(addDays(setDate(now; 1); -1); "YYYY-MM"; "Asia/Seoul")`로 전월을 조회한다. Data store 확인과 기록에도 같은 월 키를 사용한다.
3. 해당 키가 없으면 Gmail로 보내고 성공 후 Data store에 키를 저장한다. Gmail 제목과 HTML 본문은 HTTP 응답에서 가져온다.
4. 사용자가 수동 시험에서 메일 수신을 확인했고, 별도 테스트 키로 첫 실행의 발송·기록 및 두 번째 실행의 차단을 확인했다. 이후 날짜 필터와 두 키 수식을 복원했고 Active 화면을 확인했다.
5. 사용자가 수신자 네 주소를 입력한 화면을 제공했다. 최종 저장과 모든 주소의 수신 여부는 확인되지 않았다. 주소는 Make에서 직접 확인한다.

## 확인 및 운영 시 유의사항

- 첫 예약 발송은 2026-11-30 08:00에 2026-10 리포트로 예정되어 있으며, 실제 실행과 각 주소의 수신은 확인 대기다. 날짜 경계의 실제 자동 실행도 미검증이다.
- 이 API는 매번 현재 데이터를 읽는다. 발송 당시 본문 보관과 수신자별 성공 기록은 구현하지 않았다.
- 존재 확인, 메일 발송, 기록 저장은 하나의 원자적 작업이 아니다. 동시 실행이나 발송 후 기록 저장 실패 시 중복이 가능하다. 실패 후 재실행하기 전에 Make 실행 기록과 Gmail 보낸편지함을 확인한다. 수신자 일부만 수신한 경우 월별 단일 키로는 개별 성공 여부를 알 수 없다.
- Gmail 연결 화면에는 2027-05-22 16:58까지 재인증하라는 안내가 표시됐다. 만료 전에 연결을 재인증한다.
