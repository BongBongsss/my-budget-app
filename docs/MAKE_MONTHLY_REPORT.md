# Make 월간 가계부 리포트 연결 준비

현재 이 문서는 **로컬 구현과 시험 준비**에 관한 안내다. Make 시나리오, 실제 수신자, 정기 발송 및 운영 환경 설정은 아직 구성하지 않았다. 이 API는 메일을 직접 보내거나 발송 기록을 저장하지 않는다.

## 요약 조회

- `GET /api/integrations/make/monthly-report?period=YYYY-MM`
- `Authorization: Bearer <MAKE_REPORT_TOKEN>` 헤더를 사용한다. 토큰이 없거나 32자 미만이면 조회가 비활성화된다.
- 설정값은 `MAKE_REPORT_TOKEN` 환경변수이며, 무작위로 생성한 충분한 길이의 전용 값을 사용한다. 토큰과 비밀번호는 채팅·URL·문서·Git에 남기지 않는다.
- 결과에는 `subject`, `html`, `text`, `summary`가 있다. 승인 거래와 통계 제외 설정을 적용하며, 미승인 집계는 활성 임포트 행을 포함한다.
- 응답은 민감한 가계 요약이므로 `Cache-Control: no-store`를 사용한다. Make의 실행 기록과 메일함에도 정보가 보관될 수 있으므로 접근 권한과 보관 설정을 확인한다.
- 날짜는 명시된 월의 가계부 기록 기준이다. `period`는 `2026-10` 같은 형식이며 누락·잘못된 값은 거부한다.

## Make 연결 시 확인할 순서

1. 로컬 테스트와 메일 모양을 확인한다. 실제 데이터와 수신자·메일 계정은 사용자가 확인한다.
2. 서버 코드를 운영에 반영하고 운영 환경에 전용 토큰을 설정한 뒤, 인증 실패와 허용 요청을 확인한다. 로컬 주소는 Make가 직접 호출할 수 없다.
3. Make의 새 시나리오에서 HTTP 요청을 만들고 운영 서버의 위 경로를 호출한다. 토큰은 인증 헤더의 안전한 자격 증명 설정에 넣는다. 실제 메일 발송 모듈은 우선 비활성화한다.
4. 결과의 `subject`, `html`, `text`를 확인한 후 기존 메일 연결에 맞춰 발송 모듈을 구성한다. 두 사람에게 동일한 내용을 보내되 실제 수신 주소와 발송 계정은 Make에서 직접 확인한다.
5. 일정은 합의 후 설정한다. 매월 5일 오전 9시를 사용한다면 시나리오 시간대가 `Asia/Seoul`인지 확인하고, 지난달은 Make의 `formatDate(addMonths(now; -1); "YYYY-MM"; "Asia/Seoul")` 방식으로 계산할 수 있다. 해가 바뀌는 경우도 시험한다.

## 자동 발송 전 남은 작업

- 이 API는 매번 현재 데이터를 다시 읽는다. **발송 당시 내용 보관, 수신자별 성공 상태 및 중복 발송 방지 기능은 아직 구현되지 않았다.**
- Make의 재시도·중복 실행과 두 수신자 중 일부만 발송된 경우를 포함해 저장 위치와 복구 절차를 결정하고 검증한다. 단순 실행 이력만으로 중복 발송 방지를 보장하지 않는다.
- 인증정보와 실제 메일 내용을 확인한 뒤 시험 발송을 진행한다. 자동 스케줄은 시험 결과와 중복 방지 대책 확인 전까지 활성화하지 않는다.
