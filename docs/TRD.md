# TRD

- 프로젝트 루트 `AGENTS.md`에 작업 지침을 두고 `docs/`의 네 문서에 작업 상태를 기록한다. (§D1)
- 규칙 문서 수정 예외의 대상은 Codex 지침 파일 `AGENTS.md`다. (§D2)

- 공통 작업 지침은 `AGENTS.md`를 기준으로 하며 도구별 진입 문서에서 이를 안내한다. 통합 전 지침 원문은 `_archive/instructions/`에 보관하고 현행 정책으로 적용하지 않는다. (§D3)
- 문서화 적용 범위와 지침 단독 수정 예외를 명확히 하고, 위험 기반 테스트·푸시 전 검증·DB 운영 문서 참조를 공통 지침에 반영한다. (§D4)
- 검증 비대상과 미검증 상태를 구분하고, 푸시 날짜 정정·검증 불가 대응·기존 문서 확인·병렬 작업 기록 충돌 처리 기준을 둔다. (§D5)
- 제품 요구사항의 기준 문서는 루트 `BudgetSpec.md`이며 `server/BudgetSpec.md`에서 이를 안내한다. 과거 인수인계·리뷰 문서는 `_archive/history/`에 보관한다. (§D7)
- 문서별 역할은 `docs/README.md`에서 안내한다. 중복 메모의 기준은 루트 `나중에 할일.txt`이며 서버 쪽은 안내로 유지한다. (§D8)
- Windows의 Codex 사용자 설정에 `chrome-devtools` MCP를 `cmd /c npx -y chrome-devtools-mcp@latest`로 등록했으며 이후 세션에서 연결과 화면 조회를 확인했다. (§D9)
- Neon MCP는 `Read only` 선택·재연결 후에도 새 세션에서 쓰기 모드와 변경 도구가 표시되어 실제 쓰기 차단 여부가 미확인이다. 확인 전까지 쓰기가 가능하다고 간주하고 조회 위주로 사용하며, 실제 사용자 데이터에 영향을 줄 수 있는 변경은 백업 확인과 명시적 승인을 거친다. 쓰기 차단 여부를 확인하려고 운영 DB에 쓰기 시험을 실행하지 않는다. (§D10)
- 백업 복구 연습은 별도 로컬 임시 DB에 한정한다. 기존 백업의 복구·행 수 검증은 통과했으며 복구 후 화면 점검은 남아 있다. (진행중 — LOG D11)
- 운영 Neon 백업은 `server/.env`의 확인된 운영 엔드포인트만 허용하고 읽기 전용 반복 가능 읽기 트랜잭션으로 수집·파일 검증한다. Windows 예약 작업은 로그인 중 매일 09:00 확인해 둘째 월요일 이후 월 1회 검증된 백업을 남긴다. (§D12)
- Neon 수동 스냅샷 교체는 삭제 도구 접근 실패 후 사용자 요청으로 중단했으며 기존 스냅샷을 유지한다. (§D13)
