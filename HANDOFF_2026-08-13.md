# 2026-08-13 효굥봉 Fixed-cost Matching and Remember-me Update

## Summary

Today’s work refined the fixed-cost verification workflow and added a secure
remember-me login option. The existing desktop and mobile page composition was
preserved; changes are limited to fixed-cost card information, verification
controls, and the login form.

## Delivered Changes

### Fixed-cost verification

- Added confidence-based matching between registered fixed-cost items and
  imported transactions: 90 points or higher is automatically matched, 60–89
  points requires confirmation, and lower scores remain unmatched.
- Matches require the member (`효` or `굥`) to be identical, preventing one
  member’s recurring item from being matched to the other’s transaction.
- Added clear status labels: `자동 매칭 완료`, `수동 매칭 완료`, `확인 필요`,
  `중복 의심`, and `매칭 데이터 없음`.
- Shows candidate transaction details only after selecting a review/duplicate
  status, including date, merchant, amount, category, score, and the matching
  reasons.
- Added `이 거래로 확인` for manual confirmation. A confirmed merchant alias is
  remembered for that fixed-cost item, while the original transaction data is
  left unchanged.
- Added separate year and month selectors to review any imported month instead
  of only the most recent transaction month.

### Local data validation

- Prepared the local development database so it can use the same data set as
  the deployed service for fixed-cost verification.
- Added local-only database initialization, schema-repair, and restore helpers.
  These utilities are intentionally excluded from deployment commits.

### Remember-me login

- Added an optional `자동 로그인` checkbox.
- When selected, an authenticated session is renewed to a 14-day idle period
  on each revisit, but has a non-extendable 60-day maximum lifetime from the
  initial login.
- Kept the checkbox below the login button and aligned it to the right. The
  control is intended only for personal devices.

## Validation

- Fixed-cost matching: server tests and client tests passed during the related
  implementation.
- Remember-me lifetime policy: 3 focused tests passed (14-day retention,
  renewal on revisit, and expiry at the 60-day maximum).
- Login layout: client test suite passed (17 tests) and production build
  completed successfully.

## Operational hardening follow-up

- Added a single `npm run verify` release-gate command for Prisma validation,
  server type checks/tests, client tests, and the production client build.
- Confirmed existing GitHub Actions also runs browser E2E checks on push and
  monitors deployed API and client availability every 13 minutes.
- Added backup-file validation before a local restore. The latest full backup
  passed validation with 24 tables and 17,546 rows.
- Added browser coverage for automatic-login selection and the fixed-cost
  review-to-manual-confirmation workflow. The full browser suite has four
  passing scenarios.
- Measured the transaction list query locally and added an idempotent partial
  index for verified, non-deleted transactions ordered by date. The measured
  query improved from about 5 ms to about 3 ms at 4,151 transaction rows.
- Audited the legacy Prisma migration history. It is not safe to convert it
  automatically because it cannot recreate a fresh database cleanly; the
  current runtime compatibility path remains unchanged. A separate baseline
  rebuild should be planned before the next production schema change.
